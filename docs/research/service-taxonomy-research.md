# Fixi: исследование каталога автоуслуг и предложение структуры

Дата: 1 ноября 2026 года. Статус: предложение информационной архитектуры для предметной проверки и UX-тестирования.

## Решение

Для Fixi предлагается **гибридный каталог из 16 основных разделов**: знакомые клиенту задачи для ухода за автомобилем и группировка по узлам внутри технического ремонта. Три уровня: **категория → группа работ → услуга**. При этом клиент может остановиться на категории или написать симптомы без выбора конкретной работы.

На первом экране — поиск по обычным словам, автомобиль и короткие входы вроде «Шиномонтаж», «Развал-схождение», «Покраска» и «Русификация». Полный каталог раскрывается отдельно. Марки, модели, силовые установки, размеры колёс, детали кузова и материалы не размножают дерево: это фильтры и параметры заказа.

У одной услуги один постоянный ID. Она может встречаться в нескольких пользовательских маршрутах через ссылки на тот же ID. Например, полировка фар доступна из оптики и детейлинга; покраска дисков — из покраски и работ с дисками. Отклики, цены и подтверждения пользователей относятся к исходной услуге.

Это наиболее обоснованная рабочая гипотеза по результатам кабинетного исследования. Утверждение «лучший UX» потребует сравнительной проверки на автовладельцах. NN/g прямо разделяет разработку группировки методом card sorting и оценку готового дерева методом tree testing. [Card Sorting vs. Tree Testing](https://www.nngroup.com/articles/card-sorting-tree-testing-differences/), [Tree Testing](https://www.nngroup.com/articles/tree-testing/).

- [Просмотр дерева с поиском](../catalog/explorer.html): показывает пути, синонимы и карточку каждой записи. По умолчанию скрывает грузовое расширение и неподтверждённые для публикации запросы.
- [JSON](../catalog/services.json): исходные структурированные данные, 828 поисковых синонимов, перекрёстные входы, параметры, неоднозначные запросы и источники.
- [CSV](../catalog/services.csv): плоский экспорт с полным путём каждой услуги для редактирования и сверки.
- [Разбор скриншота](../catalog/screenshot-mapping.md): перенос всех 58 читаемых названий, включая объединения, разбиение и запросы на уточнение.

Числа отражают объём нашего справочника. Это не статистика востребованности услуг, число СТО или результат пользовательского тестирования.

## Охват и границы полноты

Основной каталог покрывает легковые автомобили, кроссоверы, внедорожники, пикапы и лёгкий коммерческий транспорт; обычные ДВС, гибриды, подключаемые гибриды, последовательные гибриды и электромобили. Для грузовиков, автобусов и прицепов предусмотрен дополнительный модуль: специальные узлы не выводятся владельцу легкового автомобиля без необходимости.

«Все виды работ» здесь означает охват основных семейств клиентских задач. Перечень каждой операции для каждой марки и модификации превратился бы в технологический справочник с иной гранулярностью. В него не подмешиваются продажа запчастей, аренда автомобилей, страховые продукты и отдельные каталоги мотоциклов, лодок или промышленной спецтехники.

Реальные пакеты, допустимые методы ремонта, совместимость, квалификация и наличие оборудования подтверждаются на уровне исполнителя и конкретного автомобиля. Ссылки на источники подтверждают семейства работ и наблюдения о рынке; они не означают, что каждый источник оказывает каждую предложенную нами услугу.

## Метод исследования

1. Сопоставлены публичные каталоги сетевых автосервисов и прайс-листы белорусских мастерских.
2. Отдельно изучены кузовные работы, покраска, PPF/винил/тонировка, уход за автомобилем и салон.
3. Проверены особые потребности EV: батареи, зарядка, высоковольтные узлы, термоуправление, русификация и ПО.
4. Использованы первичные материалы производителей компонентов и специалистов по трансмиссиям, дизельной аппаратуре, шинам, отоплению и ADAS.
5. Принципы группировки сверены с первичными UX-исследованиями NN/g и Baymard.
6. Категории скриншота нормализованы, синонимы отделены от самостоятельных работ, добавлены сценарии уточнения запроса.

Реестр содержит 30 первичных страниц: поставщиков услуг, производителей и исследовательских организаций. Часть наблюдений получена из доступного поискового представления страниц; для ключевых каталогов дополнительно открыт текст страниц. Запросы по некоторым известным площадкам не дали надёжно читаемого каталога — их содержимое не реконструировалось. Поиск не заменялся предположением о том, как устроены их меню.

Это desk research и экспертная нормализация. Интервью, аналитика реальных запросов Fixi, замеры конверсии, card sorting и tree testing ещё не проводились. Цены и рекламные обещания источников в справочник не переносились.

## Почему именно такая архитектура

### Варианты, которые сравнивались

| Модель | Преимущества | Ограничения | Решение |
| --- | --- | --- | --- |
| Один плоский список | Простота импорта, видны узкие термины | Смешивает цели, узлы, методы и глубину; трудно просматривать | Оставить только как экспорт для администрирования |
| Только «диагностика / ремонт / замена / установка» | Формально единообразно | Клиент сначала должен знать тип операции; покраска и детейлинг теряют собственные входы | Использовать тип операции как параметр |
| Только системы автомобиля | Удобно техническому специалисту | Плохо объясняет оклейку, химчистку, автоподбор и срочную помощь | Использовать внутри технических разделов |
| Только тип СТО / марка | Легко показать специализацию бизнеса | «СТО Tesla» ещё не сообщает, умеет ли оно ремонтировать батарею или только шины | Хранить специализацию отдельными правилами |
| Гибрид клиентских задач и систем | Поддерживает понятные входы и техническую детализацию | Нужны синонимы, связанные маршруты и последующая проверка | Рекомендуемая гипотеза |

Baymard показывает, что чрезмерное дробление сходных предложений по общим атрибутам мешает сравнению; часть таких различий лучше представлять фильтрами. Применение этого вывода к автоуслугам — наша интерпретация, а не опубликованный эксперимент с Fixi. [Overcategorization](https://baymard.com/research-articles/ecommerce-over-categorization).

### Верхний уровень

Три визуальные группы помогают просмотреть полный каталог; они не добавляют обязательный шаг перед выбором раздела.

**Обслуживание и ремонт**

1. Диагностика и проверка авто.
2. ТО и замена жидкостей.
3. Ремонт автомобиля.
4. Автоэлектрика и безопасность.
5. Электромобили и гибриды.
6. Шины, диски и развал-схождение.
7. Кондиционеры и отопление.

**Кузов, внешний вид и комфорт**

8. Кузовной ремонт.
9. Покраска автомобиля.
10. Оклейка и тонировка.
11. Мойка и детейлинг.
12. Стёкла, зеркала и оптика.
13. Салон и шумоизоляция.

**Дооснащение и помощь**

14. Мультимедиа, русификация и ПО.
15. Дооснащение, ГБО и тюнинг.
16. Эвакуация и помощь на дороге.

Сильная альтернатива для проверки: разделить «Стёкла, зеркала и оптика» на два входа, а «Ремонт автомобиля» раскрыть системными плитками прямо на странице каталога. Число 16 — результат текущего распределения задач, не универсальное UX-правило и не догма «магического количества пунктов».

### Глубина и гранулярность

- Три уровня — проектное ограничение для этого справочника, а не доказанный оптимум для любого каталога.
- Пример: «Ремонт автомобиля → Коробки передач → Ремонт АКПП».
- Пример: «Оклейка и тонировка → Защитная плёнка → Защитная оклейка кузова».
- Пример: «Электромобили и гибриды → Зарядка → Ремонт бортового зарядного устройства».
- В дереве нет отдельных веток «покраска передней левой двери BYD Han 2023»: это одна услуга с параметрами детали и автомобиля.
- Полная/частичная замена масла, тип материала, размер колеса, покрываемая зона и способ мехобработки задаются вариантами исполнения, когда не требуют отдельного клиентского сценария.
- Обобщённые услуги не дают исполнителю все компетенции автоматически. Если услуга содержит несколько вариантов работ, в профиле явно выбираются поддерживаемые варианты.
- Редкие профессиональные работы доступны через поиск и подробную группу, но не занимают место в быстрых действиях.

Промежуточная страница показывает состав категории, связанные входы и возможность «Показать все СТО этого направления». Она не должна быть пустым экраном с ещё одной кнопкой «Далее». [Baymard: category pages](https://baymard.com/ecommerce-design-examples/30-sub-category-page).

## Решения по спорным пересечениям

| Запрос / услуга | Каноническое место | Дополнительные входы и уточнения |
| --- | --- | --- |
| Диагностика двигателя | Диагностика → двигатель и ходовая | Ссылка из ремонта двигателя |
| Развал-схождение | Шины и диски → развал-схождение | Быстрый вход и ссылка из подвески. Балансировка колеса остаётся отдельной услугой. Различие описывает [Michelin](https://www.michelinman.com/auto/auto-tips-and-advice/tire-maintenance/wheel-alignment-wheel-balancing) |
| Полировка фар | Детейлинг → полировка | Ссылка из оптики |
| Покраска дисков | Покраска → детали и компоненты | Ссылка из ремонта дисков |
| PDR | Кузовной ремонт → без покраски | Ссылка из детейлинга. PDR не гарантирует применимость к любому повреждению |
| Бронирование | Требуется уточнить объект | Кузовная PPF, плёнка на фары и защитная плёнка на стекло различаются |
| Керамика | Детейлинг → покрытия | Материал покрытия параметром; ссылка рядом с защитной оклейкой |
| Антикор | Детейлинг → защитные покрытия | Ссылка из кузовного ремонта; восстановление прогнившего порога — другая работа |
| Замена лобового стекла | Стёкла → замена | Связанный вход в калибровку ADAS. Конкретная необходимость определяется по машине и процедуре; связь подтверждает [Autoglass](https://www.autoglass.co.uk/glass-repair-and-replacement/windscreen-recalibration/) |
| Русификация BYD / Zeekr | ПО → русификация | Марка, модель, рынок и версия ПО — условия совместимости |
| Обновить ПО / привязать ЭБУ / чип-тюнинг | Три разных задачи | Не объединять под одним обещанием «прошивка» |
| Зарядная станция | Дооснащение → зарядное оборудование | Связанный вход из EV, но установка wallbox не равна ремонту OBC |
| ГБО | Дооснащение → газобаллонное оборудование | Газовое топливо дополнительно фиксируется у автомобиля |
| Предпродажная подготовка | Нужен выбор цели | Техническая проверка или косметическая подготовка |

EV-раздел хранит специальные высоковольтные работы. Общие тормоза, шины, стёкла, салонный фильтр и кузовной ремонт используют те же ID, что и для других автомобилей, с проверкой применимости. Это соответствует разделению общих и специальных работ в материалах [Bosch EV](https://www.boschcarservice.com/gb/en/services/electric-and-hybrid-car-servicing/) и [Tesla Maintenance](https://www.tesla.com/support/vehicle-maintenance).

## Пользовательские маршруты

### Человек знает услугу

Поиск «сход-развал», «шумка», «русификация» или выбор крупного раздела → группа → услуга → подходящие исполнители. Поиск учитывает названия, нормализованные синонимы и путь. Системы записи `е/ё`, дефисы, регистр и распространённые сокращения нормализуются.

### Человек знает только симптом

Сохраняет автомобиль, описывает проблему и при желании добавляет фото / код ошибки. Интерфейс задаёт короткие уточнения и предлагает направления. Категория и точная услуга не обязательны. Маршрут не превращает симптом в диагноз.

Примеры:

- «Гудит компрессор» → климат, пневмоподвеска или наддув? До уточнения — поиск причины.
- «Садится АКБ» → аккумулятор 12 В или тяговая батарея?
- «Бьёт руль» → на скорости, при торможении или на неровностях?
- «Не заряжается» → модель, тип подключения, одна или несколько зарядных точек?
- «Царапина» → плёнка, лак, краска или открытый металл?

### Исполнитель подключает услуги

Выбирает автомобильные марки / модели, раскрывает нужные группы и отмечает конкретные работы. Выбор родительской группы — только удобство интерфейса, с видимым списком включаемых услуг и возможностью исключений. Требования по оборудованию, HV-компетенции и формату выезда фиксируются отдельно.

Перенос 400 строк из прайса не должен требовать 400 ручных решений при регистрации. Нужны шаблоны специализации, поиск, массовое добавление с предпросмотром и подтверждение импортированного списка. Импорт неизвестного термина отправляется на уточнение, а не создаёт ещё одну публичную категорию.

### Клиент подтверждает услугу или оставляет отзыв

Подтверждение связывается с конкретным ID услуги, исполнителем / филиалом и областью подтверждённого опыта. Нельзя переносить подтверждение «делают шиномонтаж Tesla» на «ремонтируют тяговые батареи Tesla». Переименование категории и добавление нового входа сохраняют исходные отзывы и подтверждения.

| Технология и материал | Вариант предложения и возможности СТО | Полиуретан, метод обработки ГБЦ |
| Возможность выезда, подъёмник, габариты | Филиал и условия выполнения | Приём длинного фургона |
| Название производителя материала | Атрибут предложения | Бренд плёнки не категория дерева |

## Правила данных и подбора

1. `service_id` постоянный. Структура категории и подпись могут меняться без смены идентичности услуги.
2. Один канонический родитель и несколько `crosslinks`. Они не увеличивают количество услуг.
3. Поисковый синоним не обязан однозначно вести в одну услугу. «Компрессор», «АКБ», «прошивка», «радиатор» требуют контекста.
4. Пустой список типов силовой установки в исследовательском JSON означает «не ограничено в черновике», а не подтверждённую совместимость со всеми машинами.
5. Специализация задаётся сочетанием услуги, автомобиля, метода, оборудования и филиала; глобальный флаг «работаем с маркой» недостаточен.
6. Счётчик категории — число уникальных подходящих филиалов по текущим условиям. Нельзя суммировать числа по дочерним услугам: одна СТО попадёт в несколько.
7. «Предоставляют услугу» и «доступны для отклика на заявки» — разные состояния. Импортированная карточка может присутствовать на карте без кабинета.
8. Цена включает единицу расчёта, объём, состав и ограничения. «За колесо», «за комплект», «за ось», «за деталь» и «за автомобиль» не сравниваются как одна цена.
9. Заявка может содержать несколько задач. Требуется уточнять, нужен ли один исполнитель на весь объём или несколько независимых предложений.
10. «Другое / не знаю» — способ отправить обращение или предложить новую услугу, а не бесконечная публичная корзина категорий.
11. Синонимы и объединённые ID имеют журнал изменений. Старые URL перенаправляются, исторические заказы сохраняют исходный смысл.
12. Новая услуга создаётся после проверки отличия по задаче, компетенции или составу результата; новые марка, регион или рекламное название не достаточная причина.

## Неоднозначные и специальные запросы скриншота

Полный перенос приведён в [таблице](../catalog/screenshot-mapping.md). Значения рядом с названиями на скриншоте не интерпретировались как спрос, доступность или количество проверенных СТО.

- **Ремонт балансира:** нужно различать балансирные валы двигателя и балансирный узел грузовой подвески; к балансировке колёс автоматически не относится.
- **Фрезеровка / шлифовка ГБЦ:** единый клиентский вход «Восстановление плоскости ГБЦ», с обязательным различением метода и применимости при формировании предложения. Методы не объявляются взаимозаменяемыми.
- **Ремонт стартеров и генераторов:** разделён на две компетенции.
- **Ремонт радиаторов:** уточняется система — охлаждение двигателя, кондиционер или отопитель.
- **Ремонт двигателя:** приводит в группу, а не сразу в капитальный ремонт.

Запросы об отключении иммобилайзера, изменении экологических систем и обходе SRS не смешиваются с обычным восстановлением исправности. Они сохранены в исследовательских данных с `visibility=review_required` и выключены в обычном просмотре. Перед публикацией нужны отдельное продуктовое решение, проверка условий выполнения и применимых требований. Наличие рекламы такой услуги в источнике не является доказательством допустимости её публикации или выполнения. Правовая оценка для Беларуси в это исследование не входила.

## План UX-проверки

Предлагаемый план, не проведённое исследование:

1. Провести 8–12 модерируемых сессий с владельцами ДВС, EV/гибридов и исполнителями, чтобы найти непонятные названия. Это разведочный набор, не статистическая выборка.
2. Дать участникам сгруппировать репрезентативные 40–60 услуг: регулярные, технические, эстетические, EV и неоднозначные. Не перегружать карточную сортировку всем справочником.
3. Сравнить два дерева: рекомендованное и вариант с отдельными «Стёклами» / «Оптикой» и вынесенными системами ремонта.
4. Выполнить tree test по одинаковым задачам. Зафиксировать первый выбранный раздел, успешность, прямоту пути, возвраты и непонятные названия.
5. Проверить поиск с сокращениями и симптомами, мобильное раскрытие, заявку без точной услуги и кабинет исполнителя.
6. После запуска использовать реальные поисковые запросы, нулевые результаты, выходы из веток и причины отклонения заявок для следующей версии.

Количество участников количественной проверки рассчитывается под требуемую точность и сравнение вариантов отдельно. Универсальный «правильный процент успешности» из этого кабинетного исследования не выводится. Предлагаемая продуктовая цель: ключевые задачи должны находиться без помощи модератора и без выбора заведомо неверного технического ремонта; численные пороги фиксируются до теста. Методическая основа — [NN/g IA](https://www.nngroup.com/articles/ia-study-guide/) и [Tree Testing](https://www.nngroup.com/articles/tree-testing/).

### Задачи для проверки дерева

| Сценарий | Ожидаемый вход / уточнение |
| --- | --- |
| Поменять зимние шины на летние | Шины → сезонная смена |
| После ремонта подвески машину ведёт в сторону | Диагностика / проверка углов; уточнение симптома |
| Покрасить поцарапанный бампер | Покраска → деталь; фото повреждения |
| Убрать небольшую вмятину без повреждения краски | Кузов → PDR |
| Закрыть капот защитной плёнкой | Оклейка → PPF; зона капот |
| Сделать автомобиль другого цвета плёнкой | Оклейка → изменение цвета |
| Почистить сиденья после пролитого напитка | Детейлинг → химчистка |
| Восстановить потёртый руль | Салон → перетяжка руля |
| Заменить лобовое стекло с камерой | Стёкла → замена; связанный ADAS |
| Проверить батарею подержанного электромобиля | Диагностика → состояние тяговой батареи |
| Включить русский язык на китайском автомобиле | ПО → русификация; модель и версия |
| Заменить масло в коробке | ТО → жидкости; тип коробки |
| Гудит компрессор | Уточнить систему, не назначать ремонт по одному слову |
| Поставить домашнюю зарядку | Дооснащение → зарядное оборудование |
| Машина не открывается, ключ внутри | Помощь / замки; подтверждение права доступа |
| Не знаю, что сломалось, нужен мастер | Свободное описание, общая диагностика |

## Что добавить в ближайший этап roadmap

- Проверка этого справочника с несколькими профильными СТО: механика, кузов/окраска, детейлинг, EV и электрика.
- Согласование названий верхнего уровня и исключений из публикации.
- Прототип выбора услуги и поиска по синонимам; проверка дерева по сценариям выше.
- Схема `Service`, `Category`, `Crosslink`, `Alias`, `ServiceVariant`, `ProviderCapability` и `VehicleScope`.
- Импорт прайсов через очередь сопоставления и модерацию новых терминов.
- Версионирование каталога и правила переноса отзывов / подтверждений.
